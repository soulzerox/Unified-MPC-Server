# Unified #210 slice — durable index-job history over MCP

Issue: soulzerox/Unified-MPC-Server#210 (§11 observability).
Follow-up: #678 recommended exposing status/refs/overlays/jobs over MCP; #679
(status), #681 (revisions, GC status) and #682 (bounded GC rows) landed the
first three surfaces. The durable provider job ledger is the remaining one.

## Why this slice now

`unified-mpc index job list` and the WebUI project `ThaiRagIndexJobStore`: what
each build reused, newly embedded and skipped, its miss reasons, reindex reason
and terminal failure text. `canonical_index_status` only lists the canonical
manifest job ledger (`operationId`, `manifestId`, `pending|active`), which is a
different ledger. An agent driving the runtime still cannot read the provider
history without shelling out, and `rag_index_status` requires a live `jobId`
the operator must already know.

## What lands

### 1. `rag_index_job_list` (MCP tool)

Read-only, bounded projection of `ThaiRagIndexJobStore.listForOperator`:

- optional `workspaceId` (canonical registration UUID) and `limit` (1–200,
  default 20 for terminal rows; active rows are always listed);
- per row: job id, workspace, owner, status, force, reindex reason, timestamps,
  the reuse/embedding counters the row actually recorded, miss reasons and a
  sanitized terminal `error`;
- `totalRowCount`, `matchingRowCount`, `legacyRowCount` and `returned`, so a
  truncated listing stays visible; legacy rows are counted, never attributed.

Deliberately absent: provider job ids, the raw provider `result` payload,
owner-process identity, and `legacyData`. A ledger read failure returns fixed
text; a runtime without the ledger fails closed with `missingService()`.

### 2. Service port

`McpApplicationServices.ragIndexJobList` is optional and typed with a narrow
structural projection owned by `mcp-server`, so the tool package does not
depend on `@unified-mpc/thai-rag`. The stdio runtime maps the store listing
into that projection behind `assertStorageIdentitySafe(dataPath)` and does the
sanitization/drop at the same boundary that reads the ledger.

### 3. Naming

`rag_index_job_list` is intentionally distinct from `rag_index_status` (one
live provider job), `rag_cancel_index` (mutation) and `canonical_index_status`
(canonical store health). It matches the CLI verb `index job list`.

### 4. Tests and catalog

- `rag-tools.test.ts`: bounded/default projection, workspace filter forwarding,
  sanitized error, dropped provider fields, fail-closed service and fixed error
  text.
- Runtime fixture + readiness counts: total 276 → 277, core 138 → 139,
  success matrix 122 → 123.
- `MutationSafety` marks the tool `read`.
- `docs/architecture/TOOL_CONTRACT.md` regenerated by `docs:tools`.

## Non-goals

- No mutation: no cancel, retry, prune or reap from the listing.
- No change to `rag_index_status` / `rag_cancel_index`.
- No new persistence format or migration; the ledger schema is unchanged.
- No WebUI work: the WebUI card already projects the ledger.

## Safety

- Read-only: `READ` with `readOnlyHint: true`; the store read neither migrates
  nor reaps nor writes.
- A ledger error returns fixed text, never a local path.
- Terminal rows are bounded; `matchingRowCount` keeps truncation honest.
